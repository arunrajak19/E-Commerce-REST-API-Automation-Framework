## 📌 Overview

This project is a **REST API automation framework for an E-Commerce application**, developed using **Java 21, REST Assured, Cucumber BDD, TestNG and Maven**.

The framework is designed with a focus on **reusability, maintainability, readability and realistic API workflow automation**.

It demonstrates practical API automation concepts including:

- 🔌 REST API automation using REST Assured
- 🥒 BDD implementation using Cucumber and Gherkin
- 🧱 POJO-based request and response modeling
- 🔗 API chaining between dependent requests
- 📝 Request and response logging
- 🔍 HTTP status and response validation
- ♻️ Reusable API resources and utility components
- 🧪 Test execution using TestNG
- 📦 Maven-based build and dependency management
- 🌿 Git/GitHub version control
- 🚀 Jenkins CI/CD integration
- 🔔 GitHub Webhook-based automatic build triggering

# ✨ Key Features

## 🔌 REST API Automation

REST Assured is used as the core library for creating API requests and validating responses.

The framework supports validation of:

- HTTP status codes
- Response body
- JSON fields
- Headers
- Request and response data
- API behavior

Example:

```java
given()
    .when()
    .get("/endpoint")
    .then()
    .statusCode(200);
```

## 🧱 POJO-Based Request & Response Modeling

The framework uses **POJO (Plain Old Java Object) classes** to represent API request and response payloads.

The POJO package contains models such as:

```text
pojo/
├── LoginBody.java
├── LoginResponse.java
├── OrderDetails.java
└── Orders.java
```

POJOs provide a structured Java representation of API data and help keep request and response handling clean, readable and maintainable.

### Request Flow

```text
Java POJO
    │
    ▼
Request Object
    │
    ▼
JSON Payload
    │
    ▼
REST Assured
    │
    ▼
API Endpoint
```

### Response Flow

```text
API Response
    │
    ▼
JSON Response
    │
    ▼
POJO Mapping
    │
    ▼
Java Object
    │
    ▼
Validation
```

### Benefits of POJO Modeling

- ✅ Strongly structured request and response models
- ✅ Cleaner test implementation
- ✅ Better readability
- ✅ Reusable data models
- ✅ Easier maintenance
- ✅ Reduced repetitive JSON handling
- ✅ Supports serialization and deserialization

## 🔗 API Chaining

The framework supports **API chaining**, where data generated from one API response is extracted and reused in subsequent API requests.

This allows the framework to simulate realistic business workflows where one API depends on data generated by another API.

### API Workflow

```text
       POST
        │
        │ Create Entity
        ▼
┌─────────────────┐
│ Create Resource │
└────────┬────────┘
         │
         │ Extract ID
         ▼
      resourceId
         │
         ▼
┌─────────────────┐
│  GET Resource   │
│ /resource/{id}  │
└────────┬────────┘
         │
         │ Validate
         ▼
┌─────────────────┐
│ Update Resource │
└────────┬────────┘
         │
         │ Validate
         ▼
┌─────────────────┐
│ Delete Resource │
└─────────────────┘
```

API chaining helps:

- Reuse data between dependent API calls
- Reduce hardcoded dependent values
- Simulate real-world API workflows
- Improve test maintainability
- Validate complete business flows


### Response Logging


### Logging Flow

```text
API Test
   │
   ▼
Request
   │
   ├── Log Request
   │
   ▼
API Endpoint
   │
   ▼
Response
   │
   ├── Log Response
   │
   ▼
```

Request and response logging is especially useful during CI execution because it provides additional information when troubleshooting failed API tests.

# 🥒 BDD with Cucumber

The framework uses **Cucumber BDD** to define API behavior using readable **Gherkin** scenarios.

### Example

```gherkin
Feature: E-Commerce API

  Scenario: Verify successful API response

    Given the API endpoint is available
    When I send a GET request
    Then the response status code should be 200
    And the response should contain the expected data
```

### BDD Execution Flow

```text
Feature File
     │
     ▼
Gherkin Scenario
     │
     ▼
Step Definition
     │
     ▼
REST Assured
     │
     ▼
API
     │
     ▼
Assertions
```

### Benefits

- Business-readable test scenarios
- Separation of test behavior and implementation
- Reusable step definitions
- Easier test maintenance
- Better collaboration between QA, developers and stakeholders


### Automated Workflow

```text
git push origin main
        │
        ▼
     GitHub
        │
        │ Webhook POST
        ▼
      ngrok
        │
        ▼
     Jenkins
        │
        ▼
   Git Checkout
        │
        ▼
    Maven Test
        │
        ▼
 API Automation Suite
        │
        ▼
    Test Result
```

This enables Jenkins to automatically trigger the automation job after changes are pushed to the `main` branch.

> **Note:** ngrok is used in this project to expose the locally hosted Jenkins webhook endpoint so that GitHub can communicate with Jenkins. In a production environment, Jenkins would typically be hosted on dedicated infrastructure with a stable HTTPS endpoint.
